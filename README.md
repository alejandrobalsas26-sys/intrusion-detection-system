# Antigravity-IDS

A **local, defensive IDS / SIEM-lite platform** for a Windows homelab: network
detections, file integrity monitoring, a unified SQLite audit store, a
correlation engine that turns raw events into MITRE-mapped incidents, and a
TOTP-protected read-only dashboard. Everything runs on one machine with no
cloud dependencies. This is a portfolio/homelab project — it is **not** an
enterprise SIEM and does not claim to be one.

## Tech stack

* Python 3.11+ (developed and tested on Windows 11)
* Flask + Waitress (dashboard; Waitress is the Windows-friendly production WSGI server)
* Scapy (network sensor and offline PCAP replay)
* SQLite3 with WAL — single unified event store
* cryptography (Fernet) + pyotp (TOTP MFA)

## Implemented

* **Audit store (L0)** — [`logs/`](./logs/): every module logs into one SQLite
  database (`audit_events`). Operational maintenance via `python -m logs`:
  retention purge, integrity checks, VACUUM, WAL checkpoint, and tamper-evident
  hash-chain sealing (`seal` / `verify-chain`).
* **Alerts (L1)** — [`alerts/`](./alerts/): fault-tolerant SMTP notifications
  with optional duplicate suppression (`ALERT_DEDUP_WINDOW_SECONDS`).
* **Network sensor** — [`network/`](./network/): scapy sniffer with plug-in
  detectors for ARP spoofing, SYN scans, ICMP sweeps, and DNS queries matching
  a local IOC domain watchlist. Live sniffing requires explicit consent
  (`NETWORK_MONITOR_CONSENT=true`) **and** admin privileges; thresholds are
  configured via environment variables.
* **File integrity monitoring** — [`fim/`](./fim/): SHA-256 baselines for
  critical files and directories; raises MODIFIED / DELETED / CREATED events
  (directory watches detect newly planted files) with configurable severities.
* **Detection engine** — [`detection/`](./detection/): normalization → MITRE
  ATT&CK mapping → risk scoring (0–100) → sliding-window correlation that
  writes deduplicated incidents (`python -m detection`). Rules: brute-force
  burst, password spray, success-after-failures, replay, recon→auth,
  network→FIM, and IOC matches. Optional local threat intel lists
  (`intel.py`), explainable phishing-URL analysis (`phishing.py`), and
  per-rule remediation playbooks (`playbook.py`).
* **Authentication** — [`auth/`](./auth/): TOTP MFA with Fernet-encrypted
  secrets, enrollment CLI (`python -m auth.cli`), roles (RBAC), and
  brute-force backoff.
* **Dashboard (read-only)** — [`dashboard/`](./dashboard/): Flask application
  factory with TOTP login, session-fixation mitigation, per-IP login rate
  limiting, RBAC, `/healthz`, `/readyz`, Prometheus `/metrics`, and an
  incident API (`/api/incidents`). The data layer opens SQLite through
  `file:<path>?mode=ro`, so the database engine itself rejects writes.
  Startup diagnostics: `python -m dashboard --check`.
* **AI assist (optional, off by default)** — [`ai/`](./ai/): local-LLM
  summaries of alerts/incidents (Ollama/llama.cpp/vLLM via OpenAI-compatible
  API) with a deterministic no-network fallback.
* **Offline replay** — for detection engineering without privileges:
  * JSONL events: `python -m detection.replay demo/sample_events.jsonl --sweep`
  * PCAP through the real detector stack: `python -m network.replay samples/syn_scan.pcap`
    (synthetic captures in [`samples/`](./samples/), regenerated by
    `samples/make_sample_pcaps.py`; all addresses are RFC 5737/TEST-NET).
* **Reproducible demo attack chain** — [`demo/`](./demo/): recon → brute force
  → password spray → login → real FIM tampering in a scratch directory,
  correlated into incidents. No admin rights or network access required.
* **Orchestrator CLI** — [`ids/`](./ids/):
  * `python -m ids check` — import + configuration self-test
  * `python -m ids demo` — run the demo attack chain
  * `python -m ids run --dashboard --correlator --sensor` — start selected
    components together; anything that cannot start safely (missing consent,
    privileges, or configuration) is warned about and skipped.

## Experimental

* **Vision prototype** — [`vision/`](./vision/): an OpenCV webcam demo (Haar
  cascade face/eye detection with naive blink counting). The blink gate is a
  demo heuristic, **not** robust liveness/anti-spoofing, and the module is not
  wired into detection or alerting. It needs a webcam and `opencv-python`,
  which is intentionally **not** in `requirements.txt`. The pure blink state
  machine lives in `vision/liveness.py` and is unit-tested without a camera.

## Planned (not implemented)

* Sigma rule ingestion, structured JSON logging, dashboard search
  (see [docs/ROADMAP.md](./docs/ROADMAP.md), phase 2).
* PostgreSQL backend, server-side sessions (true logout revocation),
  OpenTelemetry (phase 3). Today the platform is SQLite-only and local-only.

## Known limitations

* SQLite is a single-writer store on one machine — fine for a homelab, not a
  distributed or high-ingest environment.
* Logout clears the cookie but cannot revoke previously issued signed cookies
  (signed-cookie limitation; server-side sessions are the planned fix).
* Network detectors are threshold heuristics; tune the `*_THRESHOLD` /
  `*_WINDOW_SECONDS` env vars to your network to manage false positives.
* The live sensor needs admin rights; on an unprivileged shell use the PCAP /
  JSONL replay paths instead.
* Email alerting depends on your SMTP configuration; there is no delivery
  guarantee or paging integration.
* The vision module is a prototype (see Experimental above).

## Quick start (local, Windows-friendly)

```powershell
copy .env.example .env                 # configure secrets first
pip install -r requirements.txt
python -m ids check                    # validate imports + configuration
python -m auth.cli enroll admin ; python -m auth.cli set-role admin admin
python -m ids demo                     # generate demo events + incidents
python -m dashboard --production       # serve via Waitress (127.0.0.1:5000)
```

Run the correlation engine (`python -m detection --interval 60`) and the daily
retention/seal jobs (`python -m logs purge --vacuum`, `python -m logs seal`) as
scheduled tasks, or start components together with
`python -m ids run --dashboard --correlator`. See
[docs/DEPLOYMENT.md](./docs/DEPLOYMENT.md).

## Tests & validation

```powershell
python -m pytest -q                    # full suite
python scripts/validate.py             # compileall + pytest (+ ruff / pip-audit if installed)
```
